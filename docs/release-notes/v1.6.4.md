# Mihomo Multi v1.6.4 发布说明

v1.6.4 引入住宅出口代理链路与链路连通性测试，托盘新增接管模式切换与端口测速，并修复内核更新检查结果未同步到全局状态的问题。

## 核心更新与改动明细

### 住宅出口代理链路

- 新增「住宅出口」管理：维护带用户名 / 密码认证的 HTTP / SOCKS5 住宅代理，支持新增、编辑、删除以及密码显示切换；用户名与密码必须同时填写或同时留空。
- 端口映射可额外选择住宅出口，形成 `本地端口 → 订阅上游节点 → 住宅出口 → 目标`。每个启用的链路端口会生成独立的链路节点，多个端口可复用同一上游节点或住宅出口。
- 链路端口统一通过链路出站，不应用国内直连、绕过列表、端口 / 全局分流规则及备用节点，确保出口确定性。
- 仍被端口映射引用的住宅出口不可删除（包括已停用的端口映射）；端口选择的上游节点、住宅出口缺失或配置无效时，监听保持开启但拒绝流量（REJECT），不回退直连或仅经上游节点出站。
- 导入订阅时解析 `proxies` 中的节点间 `dialer-proxy` 引用：节点名与引用统一加上订阅命名空间，订阅重命名时同步更新，`DIRECT` 保留内置语义；缺失引用、循环引用、重复节点名与代理组引用在导入时明确报错。

### 链路测速与连通性测试

- 端口延迟测速覆盖完整链路（上游节点 → 住宅出口 → 目标），超时结果实时刷新到端口列表与托盘。
- 端口出口 IP 探测按监听端口的实际协议发起（HTTP / Mixed 使用 `http`，SOCKS5 使用 `socks5h`），SOCKS5 监听端口同样可以准确获取最终出口。
- 住宅出口管理内支持选择订阅与上游节点直接「测试连接」，无需先创建端口映射：使用独立临时 Mihomo 实例探测完整链路的延迟、最终出口 IPv4 与归属地；不修改运行中的监听配置、系统代理或 TUN，也不持久化探测配置。
- 临时诊断内核具备严格的进程隔离：Windows 使用 Job Object、Linux 使用 `PR_SET_PDEATHSIG`、macOS 使用 kqueue 退出守护，主进程退出时一并清理，避免孤儿进程。

### 托盘

- 一级菜单新增「延迟测速」，批量测试已启用监听端口的主备节点延迟，执行期间显示进行状态并防止重复触发。
- 一级菜单新增「启用 TUN」「启用系统代理」互斥开关，优先沿用当前已选端口，否则选择端口号最小的已启用监听；启用 TUN 需要管理员权限，非管理员运行时会请求提权重启。
- 端口二级菜单显示主、备节点延迟（未配置备用节点时仅显示当前延迟）；链路端口显示「上游节点 → 住宅出口名称」。
- 端口二级菜单新增「设为系统代理 / 设为 TUN 代理」勾选项，随当前接管模式显示，选择其他端口即可切换出口，再次点击可关闭对应模式。

### 修复与体验

- 修复内核更新检查结果未同步到全局 store 导致界面状态不一致的问题。
- 统一分段选择控件（协议、主题等）的滑块动画与键盘焦点提示，并遵循系统「减少动态效果」设置。
- 运行时配置应用失败时会回滚到已保存配置与原运行时配置，避免半应用状态。
- 移除过期的 TUN 规划文档。
