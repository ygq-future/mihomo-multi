# 🚀 Mihomo Multi v1.6.1 发布说明

**基于 Mihomo (Clash.Meta) 内核与 Tauri v2 构建的轻量级高性能多端口代理监听绑定桌面客户端。**

---

## 💡 本次版本核心更新亮点

v1.6.1 是一次针对**端口占用探测准确性**与**被跳过监听自动恢复**的稳定性修复版本：

### 1. 🎯 端口占用探测准确性修正
- **IPv6 监听表完整解析**：Windows 内核表读取补齐 IPv6 TCP 表（按 `MIB_TCP6ROW_OWNER_PID` 结构解析），并与 IPv4 统一复用对齐安全的查表逻辑，修正 IPv6 端口被占用时的漏检；
- **监听行识别容错**：兼容空状态字段以及无法归属到具体进程的 `PID 0` 条目，避免把内核自身的监听误判为第三方冲突。

### 2. 🔌 按监听器实际 socket 族判定占用
- **协议差异化探测**：`http` 映射仅需 TCP 可用，`mixed` / `socks` 映射需要 TCP + UDP 同时可用；
- **UDP 占用不再误伤 HTTP**：仅有 UDP 端口被占用时，`http` 映射仍可正常绑定 TCP 监听，不再被错误跳过；
- **统一判定入口**：控制器端口与内部 `egress-probe` 探针端口复用同一套 socket 族判定逻辑，行为完全一致。

### 3. 🩺 被跳过监听的自动恢复看门狗
- **10 秒占用复检**：内核运行期间每 10 秒复检一次此前因占用被跳过的端口，一旦第三方进程释放端口，立即重新生成 `runtime.yaml` 并通过 REST API 热重载，无需手动切换开关；
- **前端自动同步**：恢复完成后通过 `port-mappings-changed` 事件推送，端口列表占位状态自动刷新。

### 4. 🧭 冲突日志可定位性增强
- **占用进程直读**：端口冲突日志补充 `transport`（TCP/UDP）与 `owner_pid` 字段，可直接定位占用端口的进程，排查端口冲突不再依赖猜测。
